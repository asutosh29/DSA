# Q2–Q6. Infix ↔ Postfix ↔ Prefix Conversion and Evaluation

> **Questions:**
> - **Q2:** Write `INF_T_PostF()` which converts a given infix expression to its equivalent postfix expression.
> - **Q3:** Write `PostFE_Value()` which receives a postfix expression as input and returns its value.
> - **Q4:** Write `INF_T_PreF()` which converts a given infix expression to its equivalent prefix expression.
> - **Q5:** Write `PreFE_Value()` which receives a prefix expression as input and returns its value.
> - **Q6:** Write a main program that receives an infix expression and, using the functions from Q2 & Q4 (and their value functions), computes its value.

## Approach

A single program answers Q2–Q6. It reads an infix expression (single-digit operands) and:

1. Converts it to **postfix** using `Inf_T_postF()` → prints it, then evaluates it with `PostF_Eval()`.
2. Converts it to **prefix** using `Inf_T_preF()` → prints it, then evaluates it with `PreF_Eval()`.

All conversions and evaluations use a stack implemented on a **linear array** (a `char` stack of capacity = expression length).

| Function | Behaviour |
|----------|-----------|
| `underflow()` / `overflow()` | empty / full check on the array stack |
| `push()` / `pop()` / `stackTop()` | standard stack operations used by the converters and evaluators |
| `precedence()` | `*` `/` → 2, `+` `-` → 1 |
| `Inf_T_postF()` | shunting-yard over the infix string; `(` `)` handled; **left**-associative for equal precedence |
| `Inf_T_preF()` | reverses + flips brackets, converts with a **right**-associative scan, then reverses again — produces a genuinely valid prefix |
| `PostF_Eval()` | scans left→right; operands pushed as ints, operator pops two and pushes `calculate(op, x1, x2)` |
| `PreF_Eval()` | scans right→left; same int-value logic |

> **Fix applied while porting:** the original stored intermediate results as `char` and read them back with `- '0'`, which breaks whenever an intermediate result exceeds one digit (e.g. `3*9 = 27` came back as `27-48 = -21`). Evaluation now stores digit values as real ints, so any intermediate result is handled correctly. Parentheses and correct associativity were also added so the prefix output is genuinely equivalent.

## Sample Interaction

```
Enter an infix expression (single-digit operands, e.g. 1+2-3*9): 1+2-3*9
Postfix: 12+39*-
Postfix value: -24
Prefix: -+12*39
Prefix value: -24
```

```
Enter an infix expression (single-digit operands, e.g. 1+2-3*9): (1+2)*3
Postfix: 12+3*
Postfix value: 9
Prefix: *+123
Prefix value: 9
```

## Test Cases

| # | Input (infix) | Expected postfix | Expected postfix value | Expected prefix | Expected prefix value | Covers |
|---|---------------|------------------|------------------------|-----------------|-----------------------|--------|
| 1 | `1+2-3*9` | `12+39*-` | `-24` | `-+12*39` | `-24` | Mixed precedence, `*` binds before `+`/`-` |
| 2 | `2+3*4` | `234*+` | `14` | `+2*34` | `14` | Multiplication before addition; multi-digit result |
| 3 | `1*2+3` | `12*3+` | `5` | `+*123` | `5` | Addition before multiplication ordering |
| 4 | `(1+2)*3` | `12+3*` | `9` | `*+123` | `9` | **Parentheses** override precedence |
| 5 | `5-1-2` | `51-2-` | `2` | `--512` | `2` | **Left associativity** of `-` |
| 6 | `8/2+1` | `82/1+` | `5` | `+/821` | `5` | Division; integer result |
| 7 | `7-2*3` | `723*-` | `1` | `-7*23` | `1` | Subtraction with product |
| 8 | `(2+3)*(4-1)` | `23+41-*` | `15` | `*+23-41` | `15` | Nested parentheses, multi-digit result |
| 9 | `1+2+3` | `12+3+` | `6` | `++123` | `6` | Left associativity of `+` |

## Notes

- Single-digit operands are required (`0–9`), matching the original. Multi-digit numbers are not tokenised.
- Q6's "main program" is this file's `main()`: type one infix line and it prints the postfix, its value, the prefix, and its value.
- The same array-stack core used in Q1(i) is reused here for character data.
