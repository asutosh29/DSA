# Q3. Search for a Key Item

> **Question:** Write a function to search for a key item in a linked list named `LIST`. The function receives a head pointer to the list and the key item, and returns a pointer to the record containing the key.

## Approach

`search(head, key)` walks the list from the head, comparing `ptr->data` against `key` at every node. On a match it returns the pointer to that node; if the list is exhausted without a match it returns `nullptr`.

The `main()` program builds the list with `create()`, prints it, then enters a search loop: the user keeps entering keys until they enter `-99`. For each key the program prints:

- `data found at address <addr>!` — where `<addr>` is the pointer to the node (the array index in the linked-array version),
- or `Element not found!`.

## Representations

Two versions are provided, identical in logic and prompts:

- **`Q3.cpp`** — pointer representation (`Node*`), from `COURSE/sheet3/3.cpp`. The address printed is the actual heap address of the node.
- **`Q3_array.cpp`** — linked-array representation (`data[]` + `next_index[]`), from `THEORY/LL/LinkedArray/larray.cpp`. The "address" of a node is its index in the arrays (the linked-array analogue of a pointer).

## Compile & Run

```bash
# pointer version
g++ Q3.cpp -o Q3 && ./Q3

# linked-array version
g++ Q3_array.cpp -o Q3_array && ./Q3_array
```

## Sample Interaction (pointer version)

```
Input node (-99 to quit): 10
Input node (-99 to quit): 20
Input node (-99 to quit): 30
Input node (-99 to quit): -99

List: 10 20 30
Enter element to search (-99 to cancel): 20
20 found at address 0x55d0a4a052c0!
Enter element to search (-99 to cancel): 99
Element not found!
Enter element to search (-99 to cancel): -99
```

## Sample Interaction (linked-array version)

```
Input node (-99 to quit): 10
Input node (-99 to quit): 20
Input node (-99 to quit): 30
Input node (-99 to quit): -99
List: 10 20 30
Enter element to search (-99 to cancel): 20
20 found at index 1!
Enter element to search (-99 to cancel): 99
Element not found!
Enter element to search (-99 to cancel): -99
```

> The exact pointer address varies run to run (heap addresses); the index in the array version is deterministic — nodes are allocated from the AVAIL list starting at index 0.

## Test Cases

Both programs take the same input. Expected outputs below use `found at ...` in place of the exact address:

| # | Input (one line each) | Expected Output | Covers |
|---|-----------------------|-----------------|--------|
| 1 | `10`, `20`, `30`, `-99` then key `10` then `-99` | `List: 10 20 30` → `10 found at ...!` (index `0` in array version) | Key at head |
| 2 | `10`, `20`, `30`, `-99` then key `20` then `-99` | `20 found at ...!` (index `1`) | Key in the middle |
| 3 | `10`, `20`, `30`, `-99` then key `30` then `-99` | `30 found at ...!` (index `2`) | Key at tail |
| 4 | `10`, `20`, `30`, `-99` then key `99` then `-99` | `Element not found!` | Key absent |
| 5 | `-99` then key `5` then `-99` | `List is empty` → `Element not found!` | Empty list |
| 6 | `7`, `7`, `9`, `-99` then key `7` then `-99` | `7 found at ...!` (once — the *first* matching node, index `0`) | Duplicate keys |
| 7 | `5`, `-5`, `0`, `-99` then key `-5` then key `5` then `-99` | `-5 found at ...!` then `5 found at ...!` | Multiple searches in one run |

## Notes

- On duplicate keys the function returns the **first** node containing the key (the list is scanned left to right).
- The search is sequential — O(n) worst case.
- In the array version, `NIL = -1` plays the role of `nullptr`.
