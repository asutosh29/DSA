# Q10. Iterative Quicksort with Sort-Order Flag

> **Question:** Write a function `QUICKSORT()` implementing the **Quicksort algorithm** to sort a given array. The function should receive a flag `ORDER` indicating sort order and handle accordingly:
> - `ORDER = 0` → Ascending
> - `ORDER = 1` → Descending

## Approach

The submission is `COURSE/sheet4/10.cpp` (implementation) with the two throwaway test functions removed and a small driver added.

The function is written **iteratively** — a stack of subranges replaces recursion:

| Function | Behaviour |
|----------|-----------|
| `partition(arr, beg, end, order)` | moves the pivot `arr[beg]` to its final spot; scans right-to-left and left-to-right, swapping whenever the scan direction flag `dir` says a swap is needed. Returns `loc`, the pivot's final index |
| `quickSort(arr, low, high, order)` | pushes `[low, high]` onto two array-stacks (`lowidx`, `highidx`); pops a subrange, partitions it, and pushes any subrange still longer than 1 element — exactly what the recursive calls would have done |
| `order` flag | `0` → ascending (internal `dir = +1`), `1` → descending (internal `dir = -1`); multiplying every comparison by `dir` flips the ordering without duplicating the partitioning code |

The stack is a plain array stack (`Stack` with `S[]`, `top`, `push`/`pop`/`underflow`/`overflow`), the same shape used throughout sheets 3–5.

`main()` runs three arrays through `runTest()`, which sorts a **copy** each time — once with `ORDER = 0`, once with `ORDER = 1` — and prints original + both sorted results.

> **Quicksort core note:** the partition logic is reused verbatim from `COURSE/sheet4/10.cpp`; only the driver around it was added.

## Test Cases

| # | Input array | ORDER | Expected output | Covers |
|---|-------------|-------|-----------------|--------|
| 1 | `44 33 11 55 77 90 40 60 99 22 88 66` | 0 | `11 22 33 40 44 55 60 66 77 88 90 99` | General ascending sort |
| 2 | Same array | 1 | `99 90 88 77 66 60 55 44 40 33 22 11` | General descending sort |
| 3 | `9 7 5 3 1` | 0 | `1 3 5 7 9` | Ascending from reverse-sorted input |
| 4 | `9 7 5 3 1` | 1 | `9 7 5 3 1` | Descending on already-descending input |
| 5 | `2 4 2 1 3` | 0 | `1 2 2 3 4` | **Duplicates** preserved and ordered |
| 6 | `2 4 2 1 3` | 1 | `4 3 2 2 1` | Descending with duplicates |
| 7 | Single element `5` | 0 / 1 | `5` | **Edge: size-1 array** (quickSort early-outs, no crash) |
| 8 | Empty array `[]` | 0 / 1 | *(nothing printed)* | **Edge: size-0 array** (early-out before any stack allocation) |

> **Note:** the original `10.cpp` had no guard for empty/single-element ranges — `partition(arr, beg, beg)` can fall off the end with no return, and a 0-length range would try to size the stacks with `0` (the `Stack` constructor prints `Invalid size` and leaves `S` uninitialised). `quickSort()` now early-outs on `low >= high`, which makes cases 7–8 safe and well-defined.

## Notes

- This is the **non-recursive** variant: the recursion stack of the textbook algorithm is replaced by an explicit `Stack` of `low`/`high` indices, so `quickSort()` is `QUICKSORT()` with the required `ORDER` flag.
- The `ORDER` flag is folded into the comparisons (`dir = +1` or `-1`), so one partition routine serves both orders.
- Values are sorted in place; the driver works on copies so the original can be shown for each order.
