# Q1. Stack Operations

> **Question:** Write functions to implement the following operations w.r.t. a **Stack**:
> - `underflow()` — to check if the stack is empty
> - `overflow()` — to check if the stack is full
> - `push()` — to save a single item on the stack
> - `pop()` — to retrieve a single item from the stack
>
> Implement these when the stack is represented by:
> - (i) Linear array
> - (ii) Dynamic variable representation as a linked list
> - (iii) Linked array representation

## Representations

Three versions are provided, identical in logic, prompts, and menu:

- **`1_array.cpp`** — the stack is a fixed-capacity array `S[]` with a `top` index (`-1` = empty).
- **`1_LL.cpp`** — the stack is a linked list; `top` points to the head node and there is **no fixed capacity**.
- **`1_linked_array.cpp`** — the stack is a linked list stored in arrays: node links are `next_index[]` values into a fixed node pool, `NIL (-1)` plays the role of `nullptr`, and a free list headed by `avail` (with `get_node()` / `free_node()`) plays the role of `malloc()` / `free()`.

## Approach

| Function | Array version (`1_array.cpp`) | Linked-list version (`1_LL.cpp`) | Linked-array version (`1_linked_array.cpp`) |
|----------|-------------------------------|----------------------------------|---------------------------------------------|
| `underflow()` | `top == -1` | `top == nullptr` | `top == NIL` |
| `overflow()` | `top == size - 1` (fixed capacity) | tries to allocate a node; full only if allocation fails (dynamic, practically never full) | `avail == NIL` (fixed node pool exhausted) |
| `push()` | checks `overflow()` first, then stores at `S[++top]` | checks `overflow()`, then inserts a new node at the head (`top`) | checks `overflow()`, then `get_node()`, links it at the head (`top`) |
| `pop()` | checks `underflow()` first, then returns `S[top--]` | checks `underflow()`, then removes the head node and frees it | checks `underflow()`, then removes the head node and returns it to the free list via `free_node()` |

All three `pop()` implementations return the sentinel `-99` and print a message when the stack is empty.

## Compile & Run

```bash
# array version
g++ 1_array.cpp -o 1_array && ./1_array

# linked-list version
g++ 1_LL.cpp -o 1_LL && ./1_LL

# linked-array version
g++ 1_linked_array.cpp -o 1_linked_array && ./1_linked_array
```

## Test Cases

| # | Version | Setup / Operation | Expected Output | Covers |
|---|---------|-------------------|-----------------|--------|
| 1 | All three | `underflow()` on a fresh stack | `underflow() = true` -> `stack is empty` | Underflow on empty stack |
| 2 | All three | Push `10`, `20`, `30` | Each prints `pushed`; stack shows `30 20 10` | Push + LIFO order |
| 3 | All three | `overflow()` after pushes | Array / linked-array (size 3): `true` -> `stack is full`. Linked list: `false` -> `not full` (dynamic) | Overflow check |
| 4 | Array + linked-array | Push `40` after stack (size 3) is full | `Stack is full! 40 was not pushed.`; stack still `30 20 10` | **Failure: push on full stack** |
| 5 | All three | Pop 3 times after filling | Prints `30 popped`, `20 popped`, `10 popped`; stack ends empty | Pop + LIFO order |
| 6 | All three | `underflow()` after emptying | `underflow() = true` -> `stack is empty` | Underflow after emptying |
| 7 | All three | Pop once more on the empty stack | `Stack is empty! Nothing to pop.`; returns sentinel `-99`; no crash | **Failure: pop on empty stack** |
| 8 | All three | Push `7`, pop, push `7`, pop | Pop returns `7` each time (node freed and reused correctly) | Duplicate values / node reuse |
| 9 | LL only | Push `5`, then keep pushing many values (e.g. 100 nodes) | Every push succeeds; list keeps growing; pop returns values in LIFO order | Dynamic growth (no fixed limit) |
| 10 | Linked-array only | Push `1`, `2`, `3` (pool size 3); pop once; push `4` | Pop frees a node back to the pool, so `4` is accepted and stack shows `4 2 1` | Free-list reuse after pop |
| 11 | All three | Push `-5`, `0`, `7`; pop | Pop returns `7`; stack shows `0 -5` | Negative / zero values |
| 12 | All three | Menu choice `7` (not in menu) | `Invalid choice!` and the menu repeats | **Failure: invalid menu choice** |

## Notes

- **Array vs linked vs linked-array:** the array version is a fixed `top` index into `S[]`; the linked-list version grows dynamically on the heap, so its `overflow()` only fires if memory runs out; the linked-array version keeps a fixed node pool with an `avail` free list — `get_node()`/`free_node()` recycle nodes exactly like `malloc()`/`free()` in the pointer version.
- Popping an empty stack returns the sentinel `-99` along with a clear message — the message is the real signal of underflow, so it cannot be confused with a real `-99` value in the screenshot.
- The menu (style follows sheet-3 solutions) lets the evaluator drive every operation one at a time: push, pop, and checking both flags before/after filling and emptying the stack.
