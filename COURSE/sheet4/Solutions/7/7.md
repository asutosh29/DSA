# Q7. Heterogeneous Stack

> **Question:** Define a stack that can store data items whose data type may vary from time to time (a **heterogeneous stack**). Write functions to implement `push` and `pop` for such a stack, and test these functions.

## Approach

A single fixed-capacity array stack stores heterogeneous items. Each slot is a **`StackElement`** made of a tag plus a **union**:

- `ItemType type` — an enum tag: `TYPE_INT`, `TYPE_FLOAT`, or `TYPE_STRING`.
- `StackData value` — a union of `int`, `float`, and `char *`; only the member named by `type` is live.

| Function | Behaviour |
|----------|-----------|
| `isEmpty()` | `top == -1` — the stack has no items |
| `isFull()` | `top == size - 1` — the stack has reached the capacity the user typed at startup |
| `push(stack, int)` | tags the slot `TYPE_INT`, stores the int |
| `push(stack, float)` | tags the slot `TYPE_FLOAT`, stores the float |
| `push(stack, char *)` | **deep-copies** the string into heap memory owned by the stack, tags `TYPE_STRING` |
| `pop()` | returns the top `StackElement` (caller prints the member named by its `type`); prints `Stack Underflow` and returns an empty element when the stack is empty |
| `printStack()` | walks `top → bottom` and prints each element's value according to its tag |

`main()` first asks for the **stack capacity**, then allocates a dynamic `StackElement[]` of exactly that size, so pushing one item past the given capacity triggers a genuine `Stack Overflow`.

Every operation switches on the stored tag, so an `int` is never printed as a `float` or a `char *`.

> **Why a union:** only one member is live at a time, so all three data types share one memory slot instead of each slot reserving space for the largest type. The enum tag records *which* member is live. A string is deep-copied with `new char[]` + `strcpy()` because a union member can only hold the pointer, not the characters themselves.

## Test Cases

| # | Setup | Operation | Expected Output | Covers |
|---|-------|-----------|-----------------|--------|
| 1 | Capacity 3 | `isEmpty()` on a fresh stack | `isEmpty() = true` -> `stack is empty` | Underflow on empty stack |
| 2 | Capacity 3 | Push int `5`, float `3.14`, string `hi` | Stack prints `hi 3.14 5` (top → bottom) | Each type stores with the right tag |
| 3 | Capacity 3, filled to capacity | `isFull()` | `isFull() = true` -> `stack is full` | Overflow check on full stack |
| 4 | Capacity 3, filled to capacity | Push int `7` | `Stack Overflow`; `7` rejected; stack still `hi 3.14 5` | **Failure: push on full stack** |
| 5 | Capacity 3 | Pop three times after filling | `Popped item: hi`, then `3.14`, then `5`; stack ends empty | LIFO order across mixed types |
| 6 | Capacity 3 | Pop on the empty stack | `Stack Underflow`; no crash | **Failure: pop on empty stack** |
| 7 | Capacity 3 | Push int `-5`, `0`, `7`; pop | Pop returns `7`; stack shows `0 -5` | Negative / zero int values |
| 8 | Capacity 3 | Push float `1.5` then `2.5`; pop twice | Pop returns `2.5`, then `1.5` | Multiple floats preserve order |
| 9 | Capacity 3 | Push strings `a` and `b`; pop once | `Popped item: b`; the `b` heap copy is freed (`delete[]`); stack shows `a` | String deep-copy + LIFO; no leak on pop |
| 10 | Capacity 3 | Push strings, pop, then push a string again | New string pushed and printed correctly | Heap reuse after a string is freed |
| 11 | Capacity 1 | Push int, then push float | First push ok; second gives `Stack Overflow` | Small capacity; overflow at `top == size - 1` |
| 12 | Capacity 3 | Menu choice `8` (not in menu) | `Invalid choice!` and the menu repeats | **Failure: invalid menu choice** |
| 13 | Capacity 0 / `-2` | Start program | `Invalid capacity!`; program exits | **Failure: invalid capacity** |

## Notes

- The stack stores a mix of `int`, `float`, and string values side by side — e.g. pushing `5`, `3.14`, `hi` then popping gives `hi`, `3.14`, `5`.
- The stack capacity is read at startup and the element array is allocated on the heap with exactly that size, so `overflow` is real and testable: fill it and the next push prints `Stack Overflow`.
- **String memory:** `push(stack, char *)` copies the string into heap memory owned by the stack, and `pop()` `delete[]`s that copy after the caller has printed it, so string slots do not leak.
- This is the same enum + union `StackElement` design as `THEORY/QUEUE/het_queue.cpp` (the file name there is a misnomer — it is really a heterogeneous **stack**), reused verbatim and extended with a runtime size, underflow/overflow checks, and a menu so every operation can be tested one at a time.
