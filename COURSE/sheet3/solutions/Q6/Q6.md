# Q6. Insert Before a Key Node

> **Question:** Modify the function from **Q5** to create `insert_before()`, which inserts the integer data item **before** the key node instead of after.

## Approach

`insert_before(head, data, key)` walks the list with two pointers (`ptr` and `prev`) looking for the key node. When found:

- if `prev == nullptr` (key is at the **head**), the new node becomes the new head:
  ```
  temp->next = head; head = temp;
  ```
- otherwise the new node is spliced between `prev` and the key node:
  ```
  temp->next = ptr; prev->next = temp;
  ```

Because the head *can* change here, the function returns the new head pointer.

`main()` uses a simple loop: each iteration asks for an element to insert and the key before which to insert it, prints the list, and repeats until the user enters `-99` to exit.

## Bug Fixed

**Original bug:** when the key was *not* found, `ptr` walked off the end of the list (`ptr == nullptr`) but the code still proceeded to link the new node after `prev` — meaning the item was **silently appended to the end of the list** instead of the insertion being refused.

**Fix:** a `ptr == nullptr` check right after the search loop prints `Key not found!` and returns the list **unchanged**.

## Notes

- With duplicate keys, insertion happens before the **first** matching node.
- This is the only insertion routine in the sheet that can change the head pointer (when inserting before the first node).
